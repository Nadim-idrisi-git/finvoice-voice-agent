# Voice architecture

Provider: Gemini Live API (`gemini-3.8-live`, native audio) over a WebSocket (see [ADR 0003](adr/0003-gemini.md)).

**Hinglish first.** The voice prompt puts language rules first: natural Hinglish by default (Hindi structure with everyday English money words), mirroring the user if he switches to pure English or Hindi, Indian number words ("do hazaar teen sau saath rupaye", lakh/crore), spoken dates, and at most two short sentences per turn. Native-audio Live models pick the language themselves (no language code) and transcribe without a vocabulary prompt, so the vocabulary hint (bank and merchant names from the data plus common Hinglish money words) is appended to the system instruction instead. Tools return spoken date fields (`asOfSpoken`) so the model never reads ISO dates aloud.

**Pronunciation.** The voice prompt asks for native Hindi phonetics (as if reading Devanagari: dental vs retroflex t/d, clear aspirates, long vowels), amounts, counts, and dates spoken in Hindi words inside Hindi or Hinglish sentences, bank names spelled the Indian way, and a natural pace. The user can pick a voice in the call screen (`Kore`, `Aoede`, `Leda`, `Zephyr` female; `Puck`, `Charon`, `Orus`, `Fenrir` male); Hindi first-person grammar follows the voice's gender. Audio quality itself is not machine-tested: compare voices by ear in Hindi before a demo.

**Session setup.** The browser calls `POST /api/v1/voice/session`. The backend calls `POST https://generativelanguage.googleapis.com/v1beta/auth_tokens` with the long-lived key and a `bidiGenerateContentSetup`: `model` (`GEMINI_LIVE_MODEL`, default `gemini-3.8-live`), `responseModalities: ["AUDIO"]`, the prebuilt voice (`GEMINI_VOICE`, default `Kore`), the system instruction, the shared function declarations with `behavior: "BLOCKING"`, and input and output audio transcription. The token is single-use: it must open a session within 60 seconds and expires after 10 minutes. Only the token name reaches the browser, and the browser cannot change the locked setup.

**Media.** The browser opens `wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContentConstrained?access_token=<token>` and sends an empty `setup`. After `setupComplete`, an AudioWorklet captures the microphone (echo cancellation, noise suppression, auto gain), downsamples to 16 kHz 16-bit PCM, and sends 40 ms chunks as `realtimeInput.audio`. Model audio arrives as base64 24 kHz PCM in `serverContent.modelTurn` and is scheduled back to back on an `AudioContext`. The agent opens the call with a `clientContent` text turn.

**Events → UI state.** `inputTranscription` → `USER_SPEAKING`; `toolCall` → `PROCESSING`; first audio chunk → `ASSISTANT_SPEAKING`; `turnComplete` with playback drained → `LISTENING`; `interrupted` → `INTERRUPTED` → `USER_SPEAKING`. The user's transcript is published when the model starts answering, the assistant's on `turnComplete`. The state machine in `frontend/src/services/voiceState.js` rejects impossible jumps.

**Interruption.** Server-side VAD detects barge-in and sends `interrupted`; the browser stops every scheduled audio chunk and resets the playback queue.

**Tools.** Each `toolCall.functionCalls` entry is forwarded to `POST /api/v1/tools/:name` (the call `id` makes it idempotent), and all results go back in one `toolResponse`. Tools are declared `BLOCKING` so the model waits for results before speaking amounts. Calls named in `toolCallCancellation` are not answered. Action tools only create proposals; the UI shows a notice to confirm them.

**Teardown.** Ending the session closes the WebSocket and AudioContext and stops microphone tracks. A normal close (for example the session time limit) ends the call; any other close shows an error. Starting voice again mints a fresh token. Session resumption is not implemented.

Smoke test: `npm run voice-smoke` in `backend/` mints the same session and plays a typed Hinglish call (briefing → detail → draft → confirm), printing the spoken transcript and validator result. Model names and voices change over time; they are configurable. Naturalness with real microphone audio remains to be evaluated by ear (see `VOICE_EVALUATION.md`).
