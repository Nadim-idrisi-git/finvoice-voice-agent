The 20-second opening (memorise this)

"Your phone already knows everything about your money: UPI alerts, EMIs, insurance emails. Nobody reads them, so a double charge or a lapsed policy goes unnoticed. Finvoice is a voice agent that calls you every Sunday, reads all of it, tells you the three things that matter, and fixes one on the call. Let me show you."

Who it's for

Busy salaried Indians with multiple bank accounts, autopays and a policy or two: people who never open a finance dashboard but always pick up a call.

If the judge goes off-script

  • Any balance question: she answers with the "as of" date (IDFC ₹3,994.90, PNB 9380 ₹5,564.36, HDFC 7350 ₹14,261.39).
  • Something not in the data (CIBIL score, loan rate, room-rent limit): she says she can't verify it. That's a feature: say "it refuses to guess."
  • "Send money" or "cancel my subscription": she declines; no money movement by design.
  • Pure English or pure Hindi: she mirrors the language.

If it breaks, say what should have happened and move on (handbook rule)

  • Mic/voice fails: use the text box "Prefer typing?" (same agent, same checked numbers). Type: What should I know this week?
  • She's slow to answer: "She's pulling his records; every number is checked first."
  • Error banner: refresh once; voice reconnects with a fresh session.

Questions judges are likely to ask, with answers

The handbook says judges score Understands · Recommends · Acts · Voice. Answers are short on purpose: say the first sentence, add the second only if asked.

1. How do you know it isn't hallucinating numbers?
Every number comes from a tool over his parsed records, each fact tied to an SMS or email ID. Before an answer is shown, code checks every rupee amount against the tool results; if one doesn't match, it retries once and otherwise says it can't verify. We test this with 35 cases against the real model.
2. What did it tell the user that he didn't know?
That IDFC charged the same ₹590 fee five times on one day (₹2,360 of duplicates), and that his ₹5 lakh health cover has been off since June because his autopay mandate was cancelled.
3. What actually got done?
A reversal request letter to IDFC with the exact amounts and balance trail, and a claim intimation draft for Care Health. Both are saved in Actions after a spoken yes. We don't send anything to a bank: no real integrations, by the rules.
4. What if someone says "yes" by accident, or the model decides to confirm on its own?
Confirmation is enforced on the server: the action only executes if the user's latest words contain an explicit yes. A draft request is never treated as a yes. Voice tool calls are also deduplicated, so a retry can't run an action twice.
5. How does it handle interruptions?
OpenAI Realtime over WebRTC with semantic voice-activity detection: when you speak, playback is cut and the server truncates unplayed audio. The UI shows "Interrupted · listening".
6. Why Hinglish, and how good is it?
That's how most Indians actually talk about money. She mirrors the user's language, uses Indian number words (lakh, "do hazaar teen sau saath"), and gendered Hindi grammar that matches the voice. Text evaluation: Hinglish 10/10, Hindi 2/2.
7. Is this RAG?
Tool-based retrieval: the model fetches exact facts through tools at question time, plus keyword search over emails. We avoided vector RAG for money because similarity search can return the wrong chunk; deterministic tools give the same number every time.
8. What happens when the data doesn't have the answer?
It says so. Credit score, loan interest rate, room-rent limits aren't in the records, so it says it can't verify them and offers what it can check. Unknown is never treated as zero.
9. How did you connect the data, not just read it?
Debits are linked to mandates and accounts: the bounced NACH on PNB 9380 is linked to the Trusave Fintech autopays pulling from the same account; the lapsed policy is linked to its cancelled UPI mandate and the eligibility block.
10. Why would the insurance claim be useful if the policy was cancelled?
That's exactly the point: in a hospital moment the worst thing is false hope. It says calmly that records show no active cover on that date, the insurer decides, and still prepares the intimation so nothing is missed.
11. Isn't the ₹135 premium vs ₹37 rate card an overcharge?
Maybe, but the data doesn't say whether ₹135 is per day or per cycle, so the agent reports both values and doesn't call it an overcharge. We don't claim what the data doesn't back.
12. How fast is it?
Voice streams in real time; she says a short hello before fetching data so there's no dead air. Tool lookups are in-memory. Text answers take about 4–6 seconds including validation.
13. Security and privacy?
The OpenAI key never reaches the browser (short-lived session keys), data is scoped to the user on the server, the model never chooses user IDs, SMS text is treated as data, not instructions, and prompt-injection and cross-user requests are in our test suite.
14. Could this scale to millions of users?
The architecture can, but we haven't load-tested it and don't claim it. Next steps: real login, per-user facts in MongoDB, shared rate limits; our capacity notes estimate ~500 concurrent calls for 5M registered users.
15. What's the business model?
B2C: free weekly call, paid tier for actions (disputes filed, claims tracked, autopay clean-up), plus partner revenue for fixing problems it finds (e.g. switching to a zero-balance account) with clear disclosure.
16. What would you build next?
Read PDF attachments (credit report, loan agreements, policy wording) so it can explain coverage clauses; send the drafts via email with consent; schedule the actual weekly outbound call.
17. Did you build this today?
Answer honestly. Say which parts existed before 11 AM (the app scaffold / template) and what you built on-site today: dataset ingestion and findings, the insurance companion, Hinglish voice tuning, the validator and evaluation, and the voice-first UI. Templates are allowed; being upfront protects you.
18. Which voice stack and why not Sarvam or ElevenLabs?
OpenAI Realtime gives true speech-to-speech streaming with interruption and tool calling in one session, which made a live, interruptible Hinglish call possible in a day. Any stack was allowed.
